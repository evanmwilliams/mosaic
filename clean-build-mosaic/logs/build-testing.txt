==============================================================================
TESTING CONCLUSION (fidelity assessment)
==============================================================================
* WHAT works faithfully on this Mac:
    - The full build (CMake+Make, identical graph) -> 0 errors.
    - libtaco.dylib + taco + taco-test + taco-bench all link.
    - The compiler's front/middle-end and CODE GENERATION are faithful:
      `taco "y(i)=A(i,j)*x(j)" -f=A:ds -print-compute` emits the correct CSR
      SpMV C kernel (Test A). This exercises parsing, index-notation lowering,
      and C codegen -- the parts that don't shell out to a C compiler.
* WHAT cannot run faithfully on this Mac (by upstream DESIGN, not a build bug):
    - Anything that JIT-compiles+executes a kernel (i.e. essentially the entire
      gtest suite and `make test`). Upstream Mosaic's Module::compile() is wired
      to a specific Linux x86_64 paper-artifact environment (PATH_TO_MOSAIC_-
      ARTIFACT -> MKL/TBLIS/GSL/CUDA .so bundle, -mavx2, GNU ld). This is
      intrinsic to "how the original works"; reproducing it faithfully requires
      that Linux x86_64 artifact machine (or its Docker image), not macOS arm64.
