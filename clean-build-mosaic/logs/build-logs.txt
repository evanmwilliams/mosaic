4. CMAKE CONFIGURE  (compatibility note)
------------------------------------------------------------------------------
cmake --version    # -> 4.3.2 on this machine.
    # PROBLEM: repo's top-level CMakeLists declares cmake_minimum_required
    # (VERSION 3.4.0). CMake 4.x removed compatibility with policies < 3.5 and
    # ABORTS configure. This is purely a CMake-version gate, not a difference in
    # how Mosaic builds.
    #
    # FIDELITY DECISION: rather than editing the repo's CMakeLists (which would
    # diverge from upstream sources) or installing a 12-year-old CMake, we use
    # CMake's own documented escape hatch: CMAKE_POLICY_VERSION_MINIMUM=3.5.
    # This only relaxes the version gate; the generator (Unix Makefiles),
    # compiler, flags, targets, and ctest harness remain byte-for-byte the
    # upstream build graph. We pass it as an ENV VAR (not just -D) so it also
    # propagates into the nested googletest sub-configure that
    # BENCHMARK_DOWNLOAD_DEPENDENCIES=ON triggers.

# First attempt (-D only) failed: top-level passed but the nested googletest
# ExternalProject configure did not inherit the flag.

export CMAKE_POLICY_VERSION_MINIMUM=3.5
cmake -DCMAKE_BUILD_TYPE='Release' -DCMAKE_INSTALL_PREFIX="${HOME}" \
      -DBENCHMARK_DOWNLOAD_DEPENDENCIES=ON ../
    # Run from build/. Matches README's exact invocation (Release, install
    # prefix = $HOME, benchmark deps downloaded). Result: "Configuring done /
    # Generating done / Build files have been written to .../build". Success.

sysctl -n hw.ncpu   # -> 14 cores; build with make -j14 (README uses -j8).

The build is faithful to upstream and succeeds:
  * Same toolchain shape as README/CI: CMake + Unix Makefiles + clang.
  * Same configure flags as the README (Release, INSTALL_PREFIX=$HOME,

IMPORTANT (see logs/build-testing.txt for the test side): while the build is
faithful and the compiler's code-generation works, the upstream RUNTIME path
(Module::compile in src/codegen/module.cpp) is hardwired to a Linux x86_64
paper-artifact environment (PATH_TO_MOSAIC_ARTIFACT -> MKL/TBLIS/GSL/CUDA, plus
-mavx2 and GNU-ld -l:lib*.so syntax). That is how the original works, and it
cannot execute kernels / run the test suite faithfully on macOS arm64 without
modifying upstream source.
